# R2-invariants_and_adrs-5 — `Storage._sweep` tells the operator "nothing was published" on the partial-publish path, where siblings HAVE landed

**Severity:** major
**Where:** `packages/latence-core/src/latence_core/storage.py` — `Storage._sweep` (:271-293), reached
from `Storage._atomic_publication`'s publish-loop handler (:263-269).
**Invariant broken:** ADR-0034 (NO SILENT ERRORS — a failure surfaces as a *truthful* typed report,
not a confident false one) and `atomic_writers`' own documented contract.

## What is wrong

`atomic_writers`' docstring states the honest limit of the N-rename publish phase:

> a failure *during* the publish loop leaves the already-renamed siblings in place and sweeps the
> rest; the exception's notes name what landed.

The code does the first half and inverts the second. `_atomic_publication` correctly sweeps only
`tmp_uris[published:]` — whatever already landed stays landed — and then hands that slice to
`_sweep`, which annotates the propagating exception with a note that is hard-coded to assert the
opposite of what just happened:

```python
exc.add_note(
    f"latence.Storage: nothing was published; the partial write {tmp!r} was removed."
)
```

`_sweep` is a cleanup helper. It is handed a list of temp paths and has no knowledge of, and no
business asserting, how many siblings were published before it was called. On the pre-publish path
its claim happens to be true; on the partial-publish path it is false, and it is the *only* thing
the exception says about publication state. The notes name what was **swept** and assert nothing
landed. They never name what landed.

## Failure scenario (reproduced)

`atomic_writers([a.jsonl, b.parquet, c.bin])`, with the rename of `b.parquet` failing (transport
drop / ENOSPC / permission-denied — the exact fault the existing suite already injects):

```
ON DISK: ['a.jsonl']
NOTE: latence.Storage: nothing was published; the partial write '…/b.parquet.<tok>.tmp' was removed.
NOTE: latence.Storage: nothing was published; the partial write '…/c.bin.<tok>.tmp' was removed.
```

`a.jsonl` is on the store, published, under its real name — and the operator is told twice that
nothing was published.

This is the Export's live shape: `JsonlParquetExport.export` publishes `records.jsonl` +
`records.parquet` (+ the optional multi-vector and BM25 sidecars) through one `atomic_writers`
block. A parquet-rename failure leaves a published, corpus-**incomplete** `records.jsonl` on the
store — which under ADR-0017 IS the deliverable a downstream reader consumes — while the error
report tells the operator nothing landed. The operator's recovery decision ("nothing landed, no
cleanup needed, nothing downstream can have read it") is then the wrong one. `IcebergCorpusTable`
folds these notes verbatim into its typed `_publication_failed` message, so the false claim
propagates into the user-facing error too.

The misinformation is generated by the very mechanism C9 added to stop callers leaking cleanup
obligations.

## What to build

Make the seam real rather than adding a layer — do **not** teach `_sweep` more:

1. `_sweep` reports only its own disposal, which is all it knows: `the partial write '…' was
   removed.` (and, unchanged, the "could not be removed — delete it manually" branch). It drops the
   publication claim entirely.
2. `_atomic_publication` — the only scope that *has* the publication accounting — emits exactly one
   publication-state note before sweeping:
   - nothing landed (body failure, or the publish loop dying on its first target): `nothing was
     published.`
   - the partial-publish path: a note that NAMES the files that landed, says they stay in place,
     and states that they are an incomplete set.
3. The `destination() -> None` slot ("an identical file is already there") advances the loop but
   publishes nothing, so it must not be counted as landed.

## Acceptance criteria

- AC1 — On the partial-publish path the propagating exception carries a note that names each
  already-published target URI and does **not** anywhere claim nothing was published.
- AC2 — On the pre-publish path (body raised, or the very first rename failed) the exception still
  carries exactly one `nothing was published` note.
- AC3 — The publication-state note appears once per failed publication, not once per swept file.
- AC4 — `_sweep`'s notes still name every swept temp path, and the "store refused the delete" branch
  still names the exact surviving path (ADR-0034); the original exception is still re-raised
  untouched and never masked.
- AC5 — Regression test `test_a_partially_published_set_names_what_landed_and_never_claims_nothing_did`
  in `packages/latence-core/tests/test_storage_atomic_writer.py` fails on the pre-fix code and passes
  after; the assertion is on the notes of a real failed multi-file publication with a real file left
  on disk, not on a flag.
- AC6 — `make test` stays green; no existing test weakened or deleted.
